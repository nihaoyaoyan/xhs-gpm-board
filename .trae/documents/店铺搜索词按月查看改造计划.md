# 店铺搜索词改为按月查看

## Summary

「店铺搜索词」数据来自后台导出的**月度汇总报表**（导入脚本按单日快照写入），但目前页面沿用全局日期区间选择器，可以按任意具体日期筛选，既与数据粒度不符，也容易让用户误以为存在日粒度明细。本次改造把该页面改为**只能选择月份**查看：页面内提供月份选择器，查询区间自动取该月第一天到最后一天；该页面隐藏顶部的全局日期区间组件，其他页面不受影响。后端聚合接口与数据模型保持不变。

## Current State Analysis

- [ShopSearchTerms.tsx](file:///workspace/web/src/pages/ShopSearchTerms.tsx#L13-L31)
  - 第 14 行通过 `useRangeParams()` 取得全局 `start/end`；
  - 第 20-29 行把 `start/end` 直接传给 `api.searchTerms({ channel: 'shop', ... })`；
  - 页面本身没有任何日期/月份控件，完全依赖顶栏的全局日期区间。
- [DateRangeBar.tsx](file:///workspace/web/src/components/DateRangeBar.tsx#L7-L30)
  - 顶栏全局「近 7/30/90 天」区间选择器，读写 `useFilterStore` 的 `start/end`。
- [MainLayout.tsx](file:///workspace/web/src/layouts/MainLayout.tsx#L69-L79)
  - 第 78 行固定渲染 `<DateRangeBar />`，所有页面都会显示。
- [filter.ts](file:///workspace/web/src/stores/filter.ts#L33-L38)
  - `useRangeParams()` 返回 `shop_id/start/end/enabled`，是全局日期状态的唯一读取入口。
- [search_terms.py](file:///workspace/backend/app/api/v1/search_terms.py#L17-L46)
  - 接口接收 `start/end` 日期区间，用 `resolve_range` 后按 `SearchTerm.date` 过滤；按 `term` 聚合，返回 `range/summary/items`。按月查询时只需把 `start/end` 传为该月首尾日期，无需改后端。
- [import_search_terms.py](file:///workspace/backend/scripts/import_search_terms.py#L1-L11)
  - 明确说明“月度汇总数据按单日快照写入指定日期”，印证页面应按月聚合。
- 项目未使用过 `DatePicker` 的月份模式；`dayjs` 已在前端广泛使用（`DateRangeBar.tsx`、`filter.ts`），AntD 5 原生支持 `<DatePicker picker="month" />`。

## Proposed Changes

### 1. `web/src/pages/ShopSearchTerms.tsx`：改为本地月份筛选

- 引入 `DatePicker`、`Typography` 与 `dayjs`、`type Dayjs`。
- 新增本地状态：
  - `const [month, setMonth] = useState<Dayjs>(() => dayjs().subtract(1, 'month'));`
  - 默认展示**上一个自然月**（当前 2026-11 默认展示 2026-10，正好对应已导入的真实月报）。
- 用月份推导查询区间，不再使用全局 `start/end`：
  - `const start = month.startOf('month').format('YYYY-MM-DD');`
  - `const end = month.endOf('month').format('YYYY-MM-DD');`
  - `useRangeParams()` 只保留 `shop_id`、`enabled`。
- `queryKey` 改为 `['search-terms-shop', shop_id, month.format('YYYY-MM'), keyword, sort]`，保证切月自动重新请求。
- 在页面顶部（Alert 与 KPI 之间）增加一行筛选条：
  - 文案「统计月份」；
  - `<DatePicker picker="month" allowClear={false} value={month} onChange={(value) => value && setMonth(value)} disabledDate={(current) => current.isAfter(dayjs(), 'month')} style={{ width: 160 }} />`；
  - 辅助说明「店铺搜索词为月度汇总数据，仅支持按月查看」。
- 原有 KPI、Top10 图、关键词筛选、排序、明细表、Excel 导出逻辑全部保留；导出的仍是当前所选月份的聚合结果。
- 删除对全局 `start/end` 的引用，避免页面受顶栏日期变化影响。

### 2. `web/src/layouts/MainLayout.tsx`：该页面隐藏全局日期区间

- 复用已有的 `useLocation()`：
  - `const hideDateRange = location.pathname.startsWith('/shop-search-terms');`
- 将 `<DateRangeBar />` 改为 `{!hideDateRange && <DateRangeBar />}`。
- 仅「店铺搜索词」页隐藏；「广告搜索词」「笔记搜索词」及其他页面继续使用全局日期区间，行为不变。

### 3. `README.md`：补充页面口径说明

- 在页面清单中把「店铺搜索词」标注为“按月查看（月度汇总数据）”。
- 在搜索词导入说明中补充：导入后页面选择对应月份即可查看，月份选择器默认上一个自然月。

### 不修改的部分

- 后端 `/api/v1/search-terms` 接口、`SearchTerm` 模型、导入脚本、广告/笔记搜索词页面均不改动。
- 全局 `filter` store 不改动，避免影响其他页面。

## Assumptions & Decisions

- **按月 = 选择一个自然月，查看该月 1 日至月末的聚合结果**；不是“按月分组列出多个月份”。如需多月对比可后续扩展。
- **默认月份为上一个自然月**：月度报表通常在次月才完整，且当前真实数据为 2026-10。
- **未来月份禁选**（`disabledDate` 限制到当前月），避免展示必然为空的数据。
- **隐藏而非禁用全局日期栏**：店铺搜索词页不再需要具体日期，保留一个不可用的日期控件会造成误解；其他页面仍需要它。
- 月份切换会触发 React Query 重新请求，无需手动刷新按钮。
- 若所选月份无数据，页面沿用现有空态（KPI 显示 0/—、图表显示“暂无搜索词数据”）。
