# 小红书电商数据分析系统（XHS Insight）实现计划

## 一、概要

从零搭建一个可本地一键运行的小红书电商数据分析系统，包含 Web 工作台与 MCP 两套入口：

- **Web 前端**：React 18 + TypeScript + Vite，Ant Design 5（小红书红主题），Zustand + React Query，ECharts，React Hook Form + Zod，xlsx 前端导出。
- **后端**：FastAPI + SQLAlchemy 2.0（async）+ asyncpg + PostgreSQL，JWT 登录，APScheduler 定时增量同步，双通道评论情感分析。
- **数据源**：千帆开放平台真实 Adapter + Mock Adapter 双实现，环境变量切换，默认 Mock 保证开箱可跑。
- **MCP**：独立 FastMCP 进程，通过 REST 调用后端，暴露分析类 Tools 供大模型使用。
- **交付**：Docker Compose（db / api / mcp / web 四服务），首次启动自动迁移 + 灌入种子数据（3 个店铺、90 天订单/广告/评论）。

工作区目前为空，属于全新项目，无历史代码与框架约束，全部按上述技术栈新建。

## 五、指标口径（后端唯一实现，前后端不得重复计算）

配置项：`cost_rate`（商品成本率，默认 0.45）、`platform_fee_rate`（默认 0.05）、`return_rate`（默认 0.08）、`monthly_fixed_cost`（默认 3000 元）。

- CTR = clicks / impressions
- CVR = orders_count / clicks
- 客单价 AOV = gmv / orders_count
- **GPM = gmv / impressions × 1000**，三因子恒等式：`GPM = 1000 × CTR × CVR × AOV`
- ROI = gmv / ad_spend（ad_spend=0 时返回 null，前端显示 “—”）
- 毛利 = gmv × (1 − cost_rate − platform_fee_rate − return_rate) − ad_spend − 固定成本分摊（按当月天数分摊）
- 毛利率 = 毛利 / gmv
- **保本销售额** = (当日固定成本分摊 + ad_spend) / (1 − cost_rate − platform_fee_rate − return_rate)；分母 ≤ 0 时返回 null 并给出配置告警
- 保本达成率 = gmv / 保本销售额

计算时机：同步完成后对受影响日期重算；每日 02:00 重算最近 7 天；查询缺失日期时按需计算并落库。所有除法做零值保护，返回 `null` 而非 NaN。

## 六、后端设计

### 6.1 配置（`core/config.py`，pydantic-settings）

`DATABASE_URL`、`JWT_SECRET`、`JWT_EXPIRE_MINUTES`、`DATA_PROVIDER`、`QIANFAN_BASE_URL`、`QIANFAN_APP_KEY/SECRET`、`ANALYZER_MODE=auto|local|llm`、`LLM_BASE_URL/API_KEY/MODEL`、`MCP_API_TOKEN`、`SCHEDULER_ENABLED`、各类任务 cron 表达式、`SEED_ON_STARTUP`。

### 6.2 鉴权

- `POST /api/v1/auth/login`（JSON：username/password）→ `{access_token, user}`；`GET /api/v1/auth/me`。
- PyJWT HS256，`passlib[bcrypt]`（固定 bcrypt==4.0.1 版本）。
- 依赖 `get_current_user` 解析 Bearer；`require_service_token` 校验 `X-Service-Token`（供 MCP 调用，与用户 JWT 并行）。
- 种子账号：`admin` / `Admin@12345`（README 明示，仅供本地）。

### 6.3 数据源 Provider（`services/providers/`）

```python
class SyncProvider(Protocol):
    async def fetch_products(shop, since, until) -> list[dict]
    async def fetch_orders(shop, since, until, cursor) -> PageResult
    async def fetch_ads(shop, since, until) -> list[dict]
    async def fetch_comments(shop, since, until, cursor) -> PageResult
```

- `MockProvider`：以 `random.Random(shop_id + date)` 生成确定性数据，覆盖近 90 天；订单含退款与多 SKU，广告含曝光/点击，评论覆盖正/中/负三档并夹杂品类关键词（虾仁、三文鱼、牛肋排等），保证图表有区分度。
- `QianfanProvider`：httpx + 签名（app_key/app_secret 的 MD5/HMAC 按官方文档实现，签名函数独立可测）；接口路径、分页参数集中在文件顶部常量表，留 `# TODO: 按千帆开放平台文档核对` 标注；统一异常映射为 `ProviderError`（鉴权失败 / 限流 / 网络）。
- 工厂 `get_provider()` 按 `DATA_PROVIDER` 返回实例；两种实现输出统一内部 DTO 结构，同步层不感知来源。

### 6.4 同步服务与调度

- `SyncManager.run(shop, resource, mode)`：读 `sync_states` 游标 → 分页拉取 → 事务内 `INSERT ... ON CONFLICT (shop_id, external_id) DO UPDATE` → 更新游标与 `sync_logs` → 触发受影响日期的指标重算与 `analyzed_at IS NULL` 评论的分析。
- 资源粒度：`orders`（每 15 分钟增量）、`ads`（每 30 分钟）、`comments`（每 60 分钟）、`products`（每日 03:00 全量）、`metrics`（每日 02:00 重算 7 天）。
- APScheduler `AsyncIOScheduler` 在 FastAPI lifespan 启动，任务带 `max_instances=1`、`coalesce=True`、失败重试 2 次；`SCHEDULER_ENABLED=false` 时仅保留手动触发。
- 手动接口 `POST /api/v1/shops/{id}/sync`（body: resource, mode=incremental|backfill, days>0），返回 task 受理结果，前端轮询 `sync-logs`。

### 6.5 评论情感分析（`services/nlp/`）

- 接口 `analyze(text) -> {sentiment, score, keywords}`；`analyze_batch` 默认 20 条/批。
- `LocalAnalyzer`：jieba.posseg 提取名词/动名词作为关键词（去停用词、TF 排序取前 5），SnowNLP 打分 → ≥0.66 正 / ≤0.33 负 / 其余中性；空文本或异常落为 neutral。
- `LLMAnalyzer`：OpenAI 兼容 `/chat/completions`，要求严格 JSON（sentiment/score/keywords），超时 15s；失败、限流或返回非 JSON 时自动降级 LocalAnalyzer 并记录 `analyzer_type`。
- `factory.get_analyzer()`：`auto` 模式下有 `LLM_API_KEY` 用 LLM，否则 local；支持 `POST /comments/reanalyze` 批量重跑。

## 十一、假设与决策清单

1. 千帆接口细节（签名算法、路径、字段名）无法离线确认，真实 Adapter 以「可测骨架 + 集中常量」交付，默认 Mock 运行；这不影响其余功能完整性。
2. 单管理员账号，不引入角色权限；多店铺通过顶部切换器与 `shop_id` 作用域实现。
3. 所有指标计算只在后端；前端不做二次计算，避免口径漂移。
4. `daily_metrics` 是读路径的性能层，源数据（orders/ad_records）为唯一事实来源，可随时全量重算。
5. 评论关键词用柱状图呈现，不引入 echarts-wordcloud 额外依赖。
6. Excel 导出在前端完成（限制 5000 行），不做后端文件生成服务。
7. LLM 情感分析采用 OpenAI 兼容协议，不绑定具体厂商。
8. 金额保留 2 位小数、比率保留 4 位小数并统一在后端 round；空值序列化为 null。
